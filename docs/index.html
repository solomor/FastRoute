The problem

From one warehouse to every doorstep.

FastRoute models a single vehicle leaving a warehouse, visiting each delivery stop once, and returning home. It aims to minimize total road distance.

01 / ROAD NETWORK

Load real streets

OpenStreetMap data provides intersections and road connections, including directed streets.

02 / SHORTEST PATHS

Dijkstra & A*

Student-implemented Dijkstra and A* find shortest road paths between stops on the directed street graph.

03 / DELIVERY ORDER

Brute-Force Route Search

Exact (or budgeted) search over delivery orders on the same road-distance matrix, compared against fixed-order Dijkstra/A* tours.

Warehouse → Road network → Dijkstra / A* paths → Brute-Force order search → Map + performance comparison

Real data

Built on real, public data.

FastRoute combines real delivery-related coordinates with the real OpenStreetMap road network, so every route follows actual streets instead of straight lines.

Preprocessing pipeline

01

Validate coordinates

Discard records with missing or invalid latitude and longitude.

02

Snap to the road graph

Attach each warehouse and delivery point to its nearest road intersection.

03

Build distance matrix

Run Dijkstra between every pair of locations to get road distances.

04

Run route algorithms

Dijkstra, A*, and Brute-Force Route Search run on the same stops for a fair comparison.

Limitation: FastRoute optimizes road-network distance, not live traffic or travel time. The datasets supply real locations used to construct delivery scenarios; they are not live delivery orders.

Shortest-path method

Dijkstra's Algorithm

Finds shortest road paths on the directed OpenStreetMap graph using a binary heap. In Compare All it also draws a full multi-stop tour by chaining those paths in the sampled stop order.

Optimal paths: yesTime: O((V + E) log V)Does not reorder stops
The trade-off

Best route vs. computation cost.

Dijkstra and A* optimally solve pairwise shortest paths on nonnegative road lengths. Brute-Force Route Search optimally (or approximately, when sampled) chooses the delivery order on that distance matrix.

AlgorithmApproachGuaranteed optimal?Time complexity
DijkstraHeap shortest paths + fixed stop orderYes for path lengthsO((V + E) log V) per path
A* SearchHeuristic shortest paths + fixed stop orderYes for path lengths (admissible heuristic)Often fewer nodes than Dijkstra
Brute-Force Route SearchEnumerate / sample delivery ordersYes when exhaustive; no when sampledO(n! × n) exact; budgeted sample beyond n≈9

n = number of deliveries. The app also exposes a Bad→Semi→Best optimization ladder for each family (implementation variants, not different algorithms).

Dijkstra and A* follow the sampled stop order using shortest road paths. Brute-Force Route Search searches alternate delivery orders on the same Dijkstra distance matrix—so order quality and pathfinding cost can be compared honestly.

Project scope

What FastRoute does—and doesn't—do.

FastRoute is an educational comparison of algorithms on road-network distances. It does not currently optimize live traffic, delivery time windows, vehicle capacity, or multiple vehicles.

Future directions

Traffic-aware travel times, multiple vehicles, vehicle capacity, delivery deadlines, and more extensive reproducible experiments.
